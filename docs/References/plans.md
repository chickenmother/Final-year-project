# Plans

## Purpose

1. Align my thoughts with your actions before implementation.
2. Keep a record so each issue or implementation reason is traceable.

## Rules

1. Put plans in `docs/plans/`.
2. Keep them clear and short; use this outline:
   - Goal
   - Files to change
   - Steps
   - Validation
   - Risks / rollback
3. Move a plan to `docs/archive/` only after the feature/fix is complete and I approve.
